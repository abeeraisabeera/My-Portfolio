FraudLab — evidence before automation

A demo app that builds synthetic payment data, scores fraud risk with an explainable model, and applies clear ALLOW / REVIEW / BLOCK rules — every decision comes with evidence for why a transaction was flagged.

Problem

Real fraud systems often return “blocked” with no explanation. FraudLab teaches a safer pattern: predict risk → apply rules → show evidence.

Pipeline

generate → features → EBM → calibration → policy → evidence. Same seed yields the same synthetic dataset for reproducible experiments.

Architecture

Next.js frontend calls a FastAPI backend. The fraud/ Python package owns features, model, policy, and evidence steps. Both UI and API must run together.

Limitations

  • Not a real bank system — uses synthetic transactions
  • Designed for teaching / demo evaluation, not live payment rails
Synthetic payments → Features → EBM model → Policy rules → Evidence UI
